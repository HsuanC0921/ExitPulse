### 站對時段不完整的 API 回應

`GET /api/v1/od/radar`（含手選站對）遇到所選小時缺紀錄或涵蓋日期不一致時，回 HTTP 422：

```json
{
  "code": "hours_mismatch",
  "error": "這組時段的紀錄日期不完整，請改選可比較時段。",
  "recordedHours": { "baseline": [0, 1, 5, 6], "current": [0, 1, 5, 6] },
  "suggested": [5, 7]
}
```

上例為欄位示意。`recordedHours` 是各月份在指定平日／週末有紀錄的全部進站小時（0–23），不以所選時段截斷。`suggested` 是起點包含、終點不包含的連續時段；優先選原時段內最長可比較區間，沒有才從全天選，等長時選起點最接近原起點者，再選較早者。建議的每個小時在各自月份內須涵蓋相同且非空的日期集合；兩月份的日期與有效天數可以不同。沒有安全的共同小時時 `suggested` 為 `null`，前端應請使用者改選月份，不能自動補 0。其他涵蓋範圍錯誤維持原本的 422；探索查詢的 `unrecorded_hours` 回應維持原樣。

Python CLI 與長駐 worker 共用此 JSON（CLI 結束碼 5），API 將該輸出以 422 回傳。2022-09 對 2026-09 平日 02–07 的實際 API 整合測試確認建議為 `[5,7]`，重查回 200。前端一鍵改查由介面負責人接續整合。

## API 工作程序與收尾狀態（2026-11-18）

- API 是 FastAPI，用 2 個常駐的 Python 行程執行分析，相同條件合併、結果快取，排隊滿回 429，逾時回 504。細節與效能量測見 [API.md](API.md)。
- 驗證新版 API 用獨立埠（例如 5017），確認後才換 5011。獨立埠仍共用同一個資料庫，寫入壓測要另建測試資料庫。API 與測試工具一律用 127.0.0.1，不要用 localhost。
- 站對時段兩期紀錄不完整時 API 回 422 `hours_mismatch`，帶 `recordedHours` 與 `suggested`。雷達只有四個時段，目前資料不會觸發；探索頁的矩陣與單日可能出現，「資料依據」會列出紀錄時段。
- 地圖載入時 2 至 3 條 MapLibre「期望數字卻是 null」警告已查過：自家資料來源無 null，底圖圖層逐一隱藏重載皆為 0，來源不明，無畫面影響，列為已知無害。
