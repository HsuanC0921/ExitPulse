# 開發交接

本文件更新於 2026-11-18。開始前先讀 [CONTRIBUTING.md](../CONTRIBUTING.md) 與 [README](../README.md)。本專案有站對比較、單站往來、全網人次三種檢視。Angular 和 MapLibre 管理介面，FastAPI 執行 Python 查詢，PostgreSQL 提供旅次與站點資料。

## 本機運作

啟動方式見 [README](../README.md) 的「快速開始」：資料庫用 `docker compose up -d --wait db`，API 用 `uvicorn main:app --app-dir apps/api --host 127.0.0.1 --port 5011`，前端用 `npx ng serve`（4200）。

資料庫已匯入官方索引 2017-01 至 2026-09 共 117 個月。月匯入完成交易後才會上線，跨月參考庫有 119 站、123 別名、3,652 天和 408,216 筆站日資料。舊 SQLite、原始 CSV 快取留在 `data/`，可供遷移與重建核對。

## 使用時要知道

- 站對比較支援排行、選兩站、切換兩月與去回方向。單站按查詢月份或日期顯示往來，全網以圓面積呈現進站量。
- 日間採墨灰人流，夜間採淺灰。帶寬及箭頭數反映人次。單站標出總量和前 10 名站名、名次與人次。可按地圖上的前 10 名按鈕重新取景。逐時長條使用整天的官方資料，每一格是按進站小時計算。
- 可點地圖車站查站碼、首次正式通車、站區介紹、附近景點和出入口。首次旅次紀錄可比正式通車早。開啟出入口時在地圖標出圖釘，雙期查詢可切兩個年代查看。
- 開始前的確切出入口歷史目前只有找到官方紀錄的項目。列表顯示啟用、封閉、重開及日期，現況座標的年代待查項目用空心圖釘。OD 資料欄位止於起訖車站。
- 使用 `python tools/station_info.py --import` 更新景點和設施快照。出入口歷史來源整理在 `tools/station_info.py`。
- 曾回報 LngLat 偶發載入錯誤，先前 48 次載入未重現。若再次發生，請保留網址、堆疊和原始座標型別再追查。
- 2026-11-18 的開發頁曾因兩個共同更動分批寫入而出現 TS2339。地圖資料型別和標籤圖層現已同步。MapLibre 常量型的標籤重疊屬性要設定在獨立圖層。

### 站對時段不完整的 API 回應

`GET /api/v1/od/radar`（含手選站對）遇到所選小時缺紀錄或涵蓋日期不一致時，回 HTTP 422：

```json
{
  "code": "hours_mismatch",
  "error": "這組時段的紀錄日期不完整，請改選可比較時段。",
  "recordedHours": { "baseline": [0, 1, 5, 6], "current": [0, 1, 5, 6] },
  "suggested": [5, 7]
}
```

上例為欄位示意。`recordedHours` 是各月份在指定平日／週末有紀錄的全部進站小時（0–23），不以所選時段截斷。`suggested` 是起點包含、終點不包含的連續時段；優先選原時段內最長可比較區間，沒有才從全天選，等長時選起點最接近原起點者，再選較早者。建議的每個小時在各自月份內須涵蓋相同且非空的日期集合；兩月份的日期與有效天數可以不同。沒有安全的共同小時時 `suggested` 為 `null`，前端應請使用者改選月份，不能自動補 0。其他涵蓋範圍錯誤維持原本的 422；探索查詢的 `unrecorded_hours` 回應維持原樣。

Python CLI 與長駐 worker 共用此 JSON（CLI 結束碼 5），API 將該輸出以 422 回傳。2022-09 對 2026-09 平日 02–07 的實際 API 整合測試確認建議為 `[5,7]`，重查回 200。前端一鍵改查由介面負責人接續整合。

## 下一輪請實際改善視覺與操作

先用目前的真實資料走一次首次使用流程：從地圖看懂一站為什麼突出、切換進出方向與時段、手選兩站、打開出口年代、遇到查詢失敗並重試。選一段實際修到可交付，連同其他畫面的共用設計一起驗證。即使下一輪主要在做資料或效能，也請實際檢查這些變更在畫面上有沒有變得更好理解。

- 優先讓資料成為焦點。對照地圖中央有多少空間、哪些工具可以收起來、同一件事有沒有兩個入口。次要說明放進現有提示，主要操作用位置、按鈕狀態和即時回饋讓人看懂。
- 檢查中文字距、詞界換行、站碼與長站名、名次和人次的對齊。用真實最長的兩站、很多出入口的轉乘站、兩個峰值時段和空白時段來驗收。
- 實際操作 1440px 桌機、768px 平板、390px 與 320px 手機的淺色與深色，另測縮放、拖曳、觸控、鍵盤、減少動態效果和錯誤後的版面穩定。可用 Impeccable 加上實際截圖，或以同等設計審查替代。機械掃描和人工評分各自回報，註明未驗證的範圍。

| 一次看懂大範圍人流方向 | 用起站 × 迄站矩陣看整體，再點進地圖。地圖縮遠時先彙成區域流帶，放大後拆成車站 |

| 知道哪些變化值得追 | 自訂同時比較人次、起站占比和歷史分位數，標出跨越門檻的變化。在同一時段對照周邊站與全網趨勢 |
| 找到可能的變化線索 | 車站事件時間線，收錄新線、出口、商場、展演場館、大型活動、連假和停駛。每條附來源與日期，在圖表按日期對齊 |

| 從景點找到最好用的站 | 同時列三站、可用出口、無障礙限制及服務狀態。接上可驗證的步行網路後才提供路線和時間 |
| 在站區與地圖間不迷路 | 點名稱、圖釘、圖表或榜單能互相定位。在手機用地圖／名單切頁保留視野和目前的時間，提供可操作的鍵盤站點清單 |

## API 工作程序與收尾狀態（2026-11-18）

- API 是 FastAPI，用 2 個常駐的 Python 行程執行分析，相同條件合併、結果快取，排隊滿回 429，逾時回 504。細節與效能量測見 [API.md](API.md)。
- 驗證新版 API 用獨立埠（例如 5017），確認後才換 5011。獨立埠仍共用同一個資料庫，寫入壓測要另建測試資料庫。API 與測試工具一律用 127.0.0.1，不要用 localhost。
- 站對時段兩期紀錄不完整時 API 回 422 `hours_mismatch`，帶 `recordedHours` 與 `suggested`。雷達只有四個時段，目前資料不會觸發；探索頁的矩陣與單日可能出現，「資料依據」會列出紀錄時段。
- 地圖載入時 2 至 3 條 MapLibre「期望數字卻是 null」警告已查過：自家資料來源無 null，底圖圖層逐一隱藏重載皆為 0，來源不明，無畫面影響，列為已知無害。
